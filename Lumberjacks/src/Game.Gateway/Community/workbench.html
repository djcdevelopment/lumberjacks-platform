Quest Picker + Absorption Engine

quest-picker
LIVE

Turns a guild's real quest tracker into a single offline page where a player checks the quests they care about — and the game mod reads the result.

What that status actually meansRuns today against real guild tracker exports: the harvest, the validator, and the picker all work end to end, and the mod reads the quest-view.json the picker saves. The download below is a cold-start kit with a synthetic sample guild — verified to run from a fresh folder with nothing but Python and openpyxl.

How it works, in detail

Python (standard library, plus openpyxl for .xlsx sources) harvests real guild quest trackers into one JSON catalog per guild. render_quest_picker.py folds a catalog into a single self-contained file:// HTML page with no server and no network calls. ComfyStewardView

steward-view
LIVE

Reads a Valheim world file and answers the questions that stop being walkable once a server gets big: where is everyone building, and who owns this.

What that status actually meansThe public repo builds a fat JAR that parses a real world .db, serves a localhost API, and draws a browser heatmap. It has been used to steward high-player worlds. What is missing is a quickstart for the roughly twenty GM probe utilities — they work, but today you have to read the source to know what each one does.

ForServer stewards and GMs on worlds big enough that walking around stopped being a way to find out what is happening.

A Java fat-JAR extracts and parses a Valheim world file (.db), exposes a REST API on localhost:7080 (/api/v1/heatmap, /api/v1/points), and serves a browser heatmap viewer. Around twenty GM probe utilities sit alongside it for build-density clustering and ownership investigation.

Steam Self-Service Join

steam-join
LIVE

An invite link, a Steam sign-in, and a mod-pack zip with your credentials already in it — no config file to hand-edit.

What that status actually meansThe join flow serves on the public AM4 endpoint today — invite, Steam sign-in, personalized zip, self-service update and reissue — over HTTPS end to end (Tailscale terminates TLS at the public edge, which retires the old plaintext-credential caveat). Stated plainly, what remains: the full Steam sign-in round-trip has not been walked on this host yet (that is exactly first task SJ-1), rate limiting is not in place, it is open to the alpha cohort only, and volunteer platform readiness is recorded as NOT READY. The Valheim world itself carries no password, by operator decision while the cohort is the operator and name-known friends: the invite gates this enrollment flow, not the world, so anyone who knows the address can direct-connect without it.

ForThe next wave of playtesters — people who want to join and play without being told to edit a config file first.

MCP Mod Channel

mcp-mod-channel
DEV ONLY

A localhost MCP server that talks to the running game mod: apply a config profile, run a bounded lab test, read back what happened.

What that status actually meansIt runs, and it really does drive the live mod. It is reachable only from 127.0.0.1 with a dev key, and that is deliberate rather than unfinished: it is a development channel, never a console or shell bridge, and every mutation it can perform is whitelisted and bounded. There is no download and no remote mode.

ForMod developers, and anyone curious about wiring an AI tool to a live game process without handing it a shell.
