quest-picker

Quest Picker + Absorption Engine

LIVE

Turns a guild's real quest tracker into a single offline page where a player checks the quests they care about — and the game mod reads the result.

What that status actually meansRuns today against real guild tracker exports: the harvest, the validator, and the picker all work end to end, and the mod reads the quest-view.json the picker saves. There is no download yet — running it means cloning the public repo and running Python locally.
What it doesPython (standard library, plus openpyxl for .xlsx sources) harvests real guild quest trackers into one JSON catalog per guild. render_quest_picker.py folds a catalog into a single self-contained file:// HTML page with no server and no network calls. A player opens that page, checks the quests they want, and saves a personal quest-view.json that the game mod reads at runtime.
Who it is forGuild stewards and GMs who already keep a quest tracker and want it to reach players in-game instead of dying in a spreadsheet tab.

You will need

  • openpyxl (only for .xlsx sources)
  • A browser — the picker is a local file:// page, not a service

steward-view

ComfyStewardView

LIVE

Reads a Valheim world file and answers the questions that stop being walkable once a server gets big: where is everyone building, and who owns this.

What that status actually meansThe public repo builds a fat JAR that parses a real world .db, serves a localhost API, and draws a browser heatmap. It has been used to steward high-player worlds. What is missing is a quickstart for the roughly twenty GM probe utilities — they work, but today you have to read the source to know what each one does.
What it doesA Java fat-JAR extracts and parses a Valheim world file (.db), exposes a REST API on localhost:7080 (/api/v1/heatmap, /api/v1/points), and serves a browser heatmap viewer. Around twenty GM probe utilities sit alongside it for build-density clustering and ownership investigation.
Who it is forServer stewards and GMs on worlds big enough that walking around stopped being a way to find out what is happening.

community-telemetry

Live Community Telemetry

LOCAL ONLY

An aggregates-only telemetry API with privacy tests that fail if a player ID, name, or position ever shows up — plus the whole stack, runnable on your machine.

What that status actually meansThe aggregates API is live on P7 and the public /community page reads it. What is local-only is everything you would need to run or change it yourself: the docker stack that reproduces the whole thing and the loopback operator dashboard both run on your machine, and neither is published as a download.
What it doesAn aggregates-only v0 telemetry API (GET /api/v0/telemetry/server, /tick, /sessions, /delivery, /regions, /events, /valheim, /cutover) whose test suite asserts that no player ID, name, or position ever appears in a response. A self-contained /community page polls it. A local dev stack brings up the real thing end to end (docker compose: postgres 5435, gateway 4000, eventlog 4002, progression 4003, operatorapi 4004), and a loopback-only operator viewer renders it for a single operator.
Who it is forAnyone who wants to run the telemetry surface themselves — and anyone who would rather check the privacy claim than take it on faith.

steam-join

Steam Self-Service Join

LIVE

An invite link, a Steam sign-in, and a mod-pack zip with your credentials already in it — no config file to hand-edit.

What that status actually meansThe join flow works end to end on comfy-p7.duckdns.org today: invite, Steam sign-in, personalized zip, self-service update and reissue. The operator runbook's own caveats stand and are not softened here — the endpoint is currently plain HTTP on a non-default, world-open port with TLS built and staged but not switched on, rate limiting is not in place yet (the runbook lists it as pre-widening work), it is open to the alpha cohort only, and volunteer platform readiness is recorded as NOT READY. Until TLS is armed, the enrollment credential crosses a plaintext public link.
What it doesAn invite link opens a page that hands off to Steam OpenID sign-in. A one-use bootstrap token is exchanged for a personalized mod-pack zip with the player's credentials already baked in. Self-service update and reissue run through the same path. The per-player token is stored only as a hash.
Who it is forThe next wave of playtesters — people who want to join and play without being told to edit a config file first.

mcp-mod-channel

MCP Mod Channel

DEV ONLY

A localhost MCP server that talks to the running game mod: apply a config profile, run a bounded lab test, read back what happened.

What that status actually meansIt runs, and it really does drive the live mod. It is reachable only from 127.0.0.1 with a dev key, and that is deliberate rather than unfinished: it is a development channel, never a console or shell bridge, and every mutation it can perform is whitelisted and bounded. There is no download and no remote mode.
What it doesA local Python MCP server on 127.0.0.1:8720 (header X-Comfy-Key, dev value comfy-dev-local) speaks bidirectionally with the running mod: apply config profiles, run bounded lab motion tests through an atomic mailbox, tail mod telemetry and logs, assemble session bundles, and get local-Ollama explanations of what it just saw.
Who it is forMod developers, and anyone curious about wiring an AI tool to a live game process without handing it a shell.
